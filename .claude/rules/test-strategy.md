# 테스트 전략 가이드라인

자동화 테스트는 **단위·통합·E2E 세 가지만** 가져감.

AI로 기능 개발 시 검증 루프가 필요한데, 검증 루프를 테스트 코드로 만들어 두면 개발 효율이 좋아짐. 기능 구현 시 테스트 코드를 검증 루프로 활용할 것.

## 테스트 종류별 위치와 대상

| 종류        | 위치                                                                                                                                                                                           | 대상                                        | 지금 상태                    |
| ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------- | ---------------------------- |
| 단위 테스트 | 유틸 구현 파일 옆에 나란히 코로케이션. 세그먼트 `utils`는 `utils/getStepStates.ts` + `utils/getStepStates.test.ts`, `shared`는 `formatDate/index.ts` + `formatDate/test.ts`                     | 유틸 함수, 콘텐츠 변환, SEO 값 만들기       | vitest (`pnpm test`)         |
| 통합 테스트 | 최종 책임 컴포넌트(대부분 widgets) 폴더 안의 `test.ts(x)`                                                                                                                                        | 콘텐츠를 읽어 화면에 그리기까지 한 구획 전체 | 아직 없음. 필요해지면 Astro Container API로 씀 |
| E2E 테스트  | 전역 `src/__test__/`에 페이지 이름을 붙인 파일 (예: `postPage.test.ts`)                                                                                                                         | 페이지 단위 수행 권장                       | 아직 없음. 필요해지면 Playwright로 씀 |

## 배치 규칙

- E2E 테스트를 페이지 폴더에 두기는 애매하므로 전역 `__test__/` 폴더로 분리. 페이지 폴더에 두지 않음.
- 테스트 파일은 "인덱스 제외 나머지는 폴더로 둔다"는 네이밍 규칙의 예외. 세그먼트 `utils`의 단위 테스트는 `{구현체 이름}.test.ts`, `shared`의 단위 테스트는 폴더 안 `test.ts`로 둠.
- **훅은 테스트하지 않음.** 단위 테스트 대상은 유틸 함수이며, 훅의 동작은 해당 컴포넌트를 브라우저에서 확인하거나 통합 테스트로 검증.
- `astro:content`를 import하는 함수(`getPosts`, `renderPost` 등)는 vitest에서 돌지 않으므로 단위 테스트하지 않음. 그 안의 계산을 순수 함수로 떼어(`calculateReadingMinutes`, `groupPostsByYear`, `toSeriesList`) 테스트함.
- `.astro`의 `<script>`가 하는 판단(예: 지금 읽는 제목, 다음 테마)도 `utils`로 떼어 테스트함.

## 기대값

- 기대값은 화면에 보일 결과를 문자열로 적음. 예: `formatDate({ date, format: "long" })` → `"2026년 11월 8일"`
- 날짜는 한국 시간 기준이므로, UTC로 전날 밤인 경우처럼 시간대가 걸리는 경우를 함께 테스트함.
- 테스트용 글 데이터는 테스트 파일 안에서 `Post` 모양으로 만듦. 실제 글(`src/content/posts`)에 기대지 않음. 글이 바뀌어도 테스트가 깨지지 않게 하기 위함.
