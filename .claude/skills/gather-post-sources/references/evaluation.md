# 평가 실행

저장소 맨 위에서 `pnpm post:fixtures`를 돌리면 저장소 밖 작업 뿌리의 `_evals/f2-실행시각/`에 가짜 자료, 로컬 설정, sources, outline, interview, 답 원문을 만듭니다. 출력의 `configFile`을 `BLOG_WORK_CONFIG`로 지정합니다. 기존 실제 설정은 바꾸지 않습니다.

`scenarios.gather`는 자료 모으기, `many`는 자료가 많은 경우, `single`은 CSS 원고 하나, `two`는 두 질문 분량의 자료입니다. 단일 원고와 두 편 분량의 자료의 내용도 모두 지어낸 글이며, 함께 생성하는 개요와 인터뷰는 검사 형식을 시험하는 가상화 예제입니다. 에이전트가 개요를 고르는 평가에는 sources만 넘기고 생성된 outline을 넘기지 않습니다.

`evals/evals.json`의 `{작업 폴더}`와 `{many 작업 폴더}` 같은 칸은 이 출력의 경로로 채웁니다. 평가 환경은 해당 작업의 `sources.md`를 두고 상태를 확인한 뒤 시작합니다. 가짜 ADR과 PR에는 이미 확인할 수 있는 사실이 있고, 개인 노트는 단서만 쓸 수 있습니다.

`pnpm post:evals`는 결정적 검사 평가를 실제로 돌리고 `evaluation.json`을 같은 저장소 밖 폴더에 씁니다. HTML과 링크의 수, 읽기 제한, 개요의 통과와 실패, 인터뷰 원문 대조와 변조 검출, 평가 JSON의 형식을 확인합니다. 모델이 스킬을 잘 고르는지와 스킬 사용/미사용의 차이를 채점한 결과로 보지 않습니다. 그 실행은 별도로 합니다.

실제 자료 평가는 공용 설정을 복사해 평가 전용 설정을 `_evals`에 두고 `workDir`만 평가 폴더로 바꿉니다. 자료 경로와 PR 번호는 로컬 인자로 넘기고 저장소 파일에는 적지 않습니다. 원문과 실행 결과는 커밋하지 않습니다.
