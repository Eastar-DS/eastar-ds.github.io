# 자료의 종류

종류는 열여섯 가지로 고정합니다. 훑은 뒤 종류마다 「있음 n건」이나 「찾지 못함」을 적으려고 고정했으며, 새 종류가 필요하면 이스타에게 묻고 아래 표에 먼저 더합니다.

| 번호 | 종류 | 흔한 모양 | 주로 있는 곳 | 빠뜨리기 쉬운 까닭 |
|---|---|---|---|---|
| 1 | 해설 아티팩트 | `.html`, `<title>`이 있음 | 작업 폴더의 `artifacts`, 내려받은 파일 | 저장소 밖에 있고 PR에는 링크로만 보입니다 |
| 2 | 아티팩트 링크 | `claude.ai/artifact/…` | PR 본문, 노션 원고 | 열 수 없어서 넘어가기 쉽습니다 |
| 3 | 노션 원고 | `notion-*.md`, `notion.so` 주소 | 작업 폴더의 `notion-drafts` | 팀 문서라서 저장소에 없습니다 |
| 4 | PR | 본문, 본문 초안, 리뷰 댓글 | GitHub, 작업 폴더의 `pr` | 올린 본문에는 없고 초안에 있는 설명이 있습니다 |
| 5 | PR 그림과 도식 | `.svg`, `.png`, `user-attachments` 주소 | 작업 폴더의 `pr/diagrams` | 본문에는 주소만 있습니다 |
| 6 | 이슈 | 본문, 댓글 | GitHub | 처음 계획이 구현과 다를 때 근거가 됩니다 |
| 7 | 커밋 | 메시지, 바뀐 파일 | 저장소 | 단계가 나뉜 순서를 알려 줍니다 |
| 8 | ADR과 결정 문서 | `adr/*.md` | 저장소 | 프론트엔드 작업의 ADR이 다른 폴더에 있기도 합니다 |
| 9 | 코드 | 바뀐 파일, 테스트, 스토리 | 저장소 | 테스트 이름이 다룬 경우를 알려 줍니다 |
| 10 | 측정 기록 | `.log`, `.jsonl`, `measure-*`, `summarize-*` | 작업 폴더, `results` | 숫자의 원본이며 글의 숫자는 여기서 확인합니다 |
| 11 | 팀 보고와 발표 자료 | `report.md`, `.pdf`, `.key`, `.pptx` | 작업 폴더의 `team-report`, 내려받은 파일 | 글과 가장 비슷한 꼴인데 팀 문서입니다 |
| 12 | 에이전트 지시문과 작업 메모 | `agent-*-brief.md`, `memory/*.md` | 작업 폴더, Claude Code 메모 폴더 | 무엇을 만들라고 했는지와 정한 것이 적혀 있습니다 |
| 13 | 개인 노트 | 옵시디언 노트 | 로컬 설정의 개인 노트 뿌리 | 이스타의 생각이 있지만 개인 기록입니다 |
| 14 | 화면 캡처와 영상 | `.png`, `.mp4`, `.mov` | 작업 폴더, 내려받은 파일 | 개인 정보가 찍혀 있을 수 있습니다 |
| 15 | 바깥 자료 | 공식 문서, 다른 글의 주소 | 자료 안의 링크 | 스크립트가 찾지 않으므로 읽으며 모읍니다 |
| 16 | 이미 쓴 블로그 글 | `src/content/posts/*/index.mdx` | 블로그 저장소 | 겹치는 내용을 다시 쓰게 됩니다 |

스크립트가 종류를 정하지 못한 파일은 「기타」로 나오며, 읽어 보고 위 종류 가운데 하나로 고칩니다. 비밀값이 들었을 만한 파일은 종류를 「비밀값 의심」으로 적고 쓰임은 `열지 않음`입니다.
