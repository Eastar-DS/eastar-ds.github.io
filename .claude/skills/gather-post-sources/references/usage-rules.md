# 글에 써도 되는지 정하는 기준

정본은 `docs/content-guide.md` 11장(세컨드 브레인 기록과 개인 정보)과 7장(아티팩트를 데모로 다시 만드는 규칙)입니다. 아래 표는 자료의 종류를 정본의 줄과 잇기 위한 것이며, 표와 정본이 다르면 정본을 따르고 다른 곳을 보고합니다.

## 쓰임 값

| 값 | 뜻 | 글에서 |
|---|---|---|
| `써도 됨` | 공개된 자료이거나, 이스타가 직접 만들었고 다른 사람의 정보가 없는 자료 | 출처를 밝히고 씁니다 |
| `다시 써서 씀` | 사실과 숫자와 생각은 쓰되 문장, 화면, 코드를 그대로 넣지 않는 자료 | 블로그 규칙에 맞게 새로 만듭니다 |
| `단서만` | 이스타의 생각이나 결정이 적혀 있지만 개인 기록인 자료 | 글에 넣지 않고 인터뷰 질문의 재료로 넘깁니다 |
| `이스타 확인` | 공개해도 되는지 판단이 서지 않는 자료 | 답을 받을 때까지 쓰지 않습니다 |
| `쓰면 안 됨` | 정본 11장이 막는 자료 | 쓰지 않고 내용도 베끼지 않습니다 |
| `열지 않음` | 비밀값이 들었을 만한 파일과 브라우저 프로필 | 이름만 적습니다 |
| `관련 없음` | 훑다가 걸렸지만 주제와 닿지 않는 자료 | 쓰지 않습니다 |

## 판정 순서

위에서부터 보고 처음 맞는 값을 적습니다.

1. 스크립트가 `열지 않음`으로 표시했으면 그대로 둡니다.
2. 로컬 설정의 「읽지 않는 곳」 아래이거나, 회의 글, 대화 기록, 인터뷰 원문이면 `쓰면 안 됨`입니다.
3. 가릴 이름이 들어 있다고 스크립트가 표시한 자료는 `써도 됨`으로 적지 않습니다. 이름을 뺀 사실을 쓸 수 있으면 `다시 써서 씀`, 이름과 떼기 어려우면 `쓰면 안 됨`입니다.
4. 개인 노트와 작업 메모는 `단서만`입니다.
5. 해설 아티팩트, 노션 원고, 팀 보고, PR 그림은 `다시 써서 씀`입니다. 아티팩트를 만든 대화 내용은 `쓰면 안 됨`입니다.
6. 공개 저장소의 PR 본문, 커밋, ADR, 코드, 이슈는 `써도 됨`입니다. 비공개 저장소면 `이스타 확인`입니다. 리뷰 댓글은 다른 사람의 글이므로 `이스타 확인`입니다.
7. 측정 기록은 이스타가 직접 잰 숫자면 `써도 됨`입니다. 운영 환경의 사용자 수, 워크스페이스 수처럼 서비스 안쪽 숫자는 `이스타 확인`입니다.
8. 화면 캡처와 영상은 `이스타 확인`입니다. 주소창, 계정 이름, 다른 탭이 찍혔는지는 사람이 봐야 합니다.
9. 어느 줄에도 맞지 않으면 `이스타 확인`입니다.

## 까닭 칸에 적는 말

「정본 11장 첫 줄」, 「공개 저장소」, 「이스타가 직접 잼」, 「팀 문서」, 「이름 규칙」처럼 짧게 적습니다. `이스타 확인`이면 무엇을 확인해야 하는지 적습니다(예: 「운영 워크스페이스 수를 공개해도 되는지」).

## 한 줄 설명 칸에 적는 말

무엇에 대한 자료인지와 글에 쓸 만한 것(그림 수, 숫자가 있는지)을 적습니다. 쓰임이 `단서만`, `쓰면 안 됨`이면 주제만 40자 안으로 적고 내용은 적지 않습니다. 파일의 제목을 그대로 적을 때는 백틱으로 감쌉니다.
