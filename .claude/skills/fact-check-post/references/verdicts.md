# 판정과 출처

## 목차

1. 주장으로 보는 것
2. 주장 종류마다 먼저 열 출처
3. 판정 여섯 가지의 조건
4. 근거를 적는 법
5. 경계에 있는 경우

## 1. 주장으로 보는 것

읽는 사람이 「정말인가」 하고 따져 볼 수 있는 문장은 모두 주장입니다.

- 숫자와 단위(시간, 길이, 개수, 비율, 배수, 범위)
- 버전과 날짜, PR과 ADR의 번호, 커밋
- 코드 이름(함수, 속성, 파일, 상수)과 코드 칸의 내용
- 동작 설명(브라우저, React, 라이브러리, 도구가 어떻게 움직인다는 말)
- 비교와 차례(「더 빠르다」, 「처음」, 「~부터」, 「~만」)
- 링크가 걸린 문장(링크한 페이지가 그 말을 한다는 주장)

`claims.json`은 정규식으로 뽑은 후보라서 숫자가 없는 동작 설명과 비교는 들어 있지 않습니다. 글을 처음부터 끝까지 읽으며 빠진 주장을 `M1`, `M2`처럼 번호를 붙여 더합니다.

## 2. 주장 종류마다 먼저 열 출처

위에 있는 출처가 1차 출처입니다. 1차 출처를 열 수 있는데 아래 것만 보고 「맞음」으로 적지 않습니다.

| 주장 | 먼저 열 출처 | 그다음 |
|---|---|---|
| 직접 잰 값 | 측정 결과 파일과 측정 로그 | 그 값으로 쓴 PR 본문, ADR |
| 글 안에서 계산한 값(줄어든 비율, 차, 배수) | 글과 출처의 값으로 다시 한 계산 | 없음 |
| 코드 이름, 코드 칸 | 글이 말하는 커밋이나 PR 기준의 저장소 사본 | PR의 diff |
| 프로젝트의 버전, 날짜, 번호 | 그 커밋의 `package.json`, `git log`, PR 페이지 | ADR |
| 브라우저와 웹 API의 동작 | 규격, MDN, 브라우저 회사의 문서와 버그 페이지 | 없음 |
| React와 라이브러리의 동작 | 공식 문서, 릴리스 노트, 그 버전의 소스 | 없음 |
| 링크가 걸린 문장 | 링크한 그 페이지 | 그 페이지가 가리키는 원문 |

해설 아티팩트와 노션 초안, 남이 정리한 글은 2차 출처입니다. 2차 출처에서만 찾은 주장은 「일부 맞음」이고, 근거에 「2차 출처에서만 찾음」이라고 적습니다. `docs/content-guide.md` 7.4가 아티팩트의 설명을 그대로 믿지 말라고 정한 것과 같은 까닭입니다. 같은 원문을 되풀이한 글 여러 개는 출처 하나로 셉니다.

## 3. 판정 여섯 가지의 조건

| 판정 | 적을 조건 | 꼭 적을 것 |
|---|---|---|
| 맞음 | 값, 단위, 조건(기기, CPU 배율, 날짜, 대상)이 모두 같음 | 출처, 근거 |
| 일부 맞음 | 값은 같은데 조건이 다름, 주장의 일부만 출처에 있음, 반올림이나 범위가 다름, 2차 출처뿐임 | 출처, 근거, 어디가 모자란지, 고칠 말 |
| 다름 | 출처가 같은 조건에서 다른 값이나 동작을 말함 | 글의 문장과 출처의 인용 둘 다, 고칠 말 |
| 출처에 없음 | 연 출처에 그 사실이 없음. 열 출처가 아예 없을 때도 여기 | 찾은 곳(파일과 찾은 낱말), 할 수 있는 일 |
| 못 엶 | 파일이 없음, 주소가 응답하지 않음, 로그인이 필요함 | 실패한 까닭(응답 코드나 오류) |
| 대조 안 함 | 의견, 생각과 경험, 〔이스타 확인〕 표시, 주장이 아닌 후보(예시로 든 숫자) | 까닭 |

## 4. 근거를 적는 법

근거 칸은 아래 셋 가운데 하나로 시작합니다. `verify`가 접두어와 인용을 검사합니다.

| 접두어 | 쓰는 때 | 예 |
|---|---|---|
| `인용:` | 출처에 같은 말이 글자 그대로 있을 때. 「」 안에 한 문장 이하로, 뒤에 위치 | 인용: 「966ms에서 46ms로 줄였습니다」 (16줄) |
| `계산:` | 출처의 값으로 계산해야 글의 값이 나올 때. 입력 값의 위치와 식 | 계산: x4 toPaint 12개의 가운데값 = (951 + 981) / 2 = 966 |
| `명령:` | 저장소 사본에서 찾거나 세어 본 결과일 때. 명령과 출력의 첫 줄 | 명령: `git grep -n getRowOffsets 9ad2653 -- frontend` → `…/getRowOffsets.ts:12:` |

- 인용은 출처의 글자를 바꾸지 않습니다. 길면 앞뒤를 자르고, 가운데를 줄이지 않습니다.
- 웹 페이지는 원문을 작업 폴더의 `fetched/` 아래에 받아 두고(`fetched/C7.html`), 출처 칸에 주소와 받은 파일 이름을 함께 적습니다. 요약 도구가 돌려준 문장은 인용으로 쓰지 않습니다.
- 날짜가 지나면 바뀌는 사실(버전, 문서의 문장)은 연 날짜를 적습니다.

## 5. 경계에 있는 경우

- 같은 값이 글의 여러 줄에 나오면 주장 하나로 묶고 줄 번호를 모두 적습니다. 줄마다 값이 다르면 출처와 견주기 전에 「다름」이고, 근거에 서로 다른 줄을 적습니다. 같은 시리즈의 다른 편과도 견줍니다.
- 한 문장에 사실이 여럿이면 주장을 나눕니다. 「Windows와 Linux를 지원한다」에서 하나만 출처에 있으면 「일부 맞음」입니다.
- 「약 20%」, 「열 개 남짓」처럼 어림한 값은 출처의 값을 같은 자릿수로 반올림해 견줍니다. 반올림해도 다르면 「다름」입니다.
- 조건이 붙은 값(CPU 4배 느림, 세션 녹화 켬)은 조건까지 같아야 「맞음」입니다. 값만 같고 조건이 다른 줄을 인용하지 않습니다.
- 코드 칸은 글이 줄여 쓴 곳(「…」 주석)을 빼고 원본과 견줍니다. 이름, 인자, 조건식이 다르면 「다름」이고, 줄바꿈과 들여쓰기만 다르면 「맞음」입니다.
- 출처가 서로 다른 말을 하면(PR 본문과 측정 파일) 1차 출처를 따르고, 둘 다 인용해 「일부 맞음」으로 적습니다.
- 링크한 페이지가 대문이고 그 말이 하위 페이지에 있으면 「일부 맞음」이고, 고칠 말에 맞는 주소를 적습니다.
