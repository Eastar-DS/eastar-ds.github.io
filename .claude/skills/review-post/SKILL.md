# 새 독자 검토

React와 브라우저 렌더링은 알지만 Knot와 이 시리즈는 처음 보는 프론트엔드 개발자로 읽습니다. 글쓴이가 의도했을 설명을 추측해서 채우지 말고, 글에 실제로 적힌 설명만으로 따라갈 수 있는지 봅니다.

## 시작 조건과 읽을 자료

- 글을 썼거나 고친 세션은 이 검토를 맡지 않습니다. 작성 대화나 해설을 넘겨받지 않은 새 세션에서 시작합니다. 현재 세션이 글쓴이라면 새 검토 세션이 필요하다고 알리고 스스로 검토를 끝냈다고 하지 않습니다.
- 검토할 글의 경로와 아래 기준만 받습니다. 작성자의 의도나 예상 문제 목록은 받지 않습니다.
- [blog-voice](../blog-voice/SKILL.md)와 [수정 전후 예시](../blog-voice/references/examples.md), [writing-style](../writing-style/SKILL.md)을 읽습니다. 형식 기준이 필요할 때 `docs/content-guide.md`를 참고하되 사용자의 명시 규칙을 우선합니다.
- `nl -ba src/content/posts/{slug}/index.mdx`처럼 원본 줄 번호를 붙여 글을 위에서부터 읽습니다. 앞머리와 import를 포함한 파일의 줄 번호를 씁니다.
- 글에서 불러오는 그림, 데모, 표, caption과 alt를 함께 봅니다. 그림은 가능하면 눈으로 확인하고, 데모는 화면 글자와 조작 안내도 읽습니다. 확인할 수 없는 그림이나 상태는 「확인 못함」으로 적습니다.

첫 독해에서는 앞 편, Knot 구현 코드, 작성 기록을 열지 않습니다. 이 편의 설명으로 걸리는 곳을 먼저 적습니다. 그 뒤 앞 편 링크의 설명이 도움이 되는지만 확인하고, 링크로 풀리는 문제와 이 편에서 설명이 필요한 문제를 구별합니다.

## 찾을 것

| 종류 | 새 독자가 걸리는 까닭 |
| --- | --- |
| 처음 보는 말 | 서비스 안쪽 이름, 탭 이름, 기술 용어가 풀이나 그림 없이 먼저 나옴 |
| 정의 없이 쓴 말 | 글쓴이가 만든 말의 대상이 없거나, 같은 대상을 다른 이름으로 부름 |
| 흐린 말 | 「근처」, 「몇 개」처럼 대상과 범위를 알 수 없음 |
| 건너뛴 설명 | 원인에서 결정으로 가는 근거가 빠지거나, 계산 조건이 없어 숫자를 따라갈 수 없음 |
| 절의 역할 섞임 | 원인 시험을 방법 비교에 넣는 등 그 절이 답할 질문과 내용이 다름 |
| AI가 쓴 느낌 | 내용 없는 예고, 정의와 조건을 몰아넣은 문장, blog-voice 10장이나 writing-style에 걸리는 표현 |
| 비교 설명 | 공통점을 한 방법의 장점으로 쓰거나, 어느 구조에서 생기는 제약인지 알 수 없음 |
| 측정 설명 | 누가 무엇을 쟀는지 모름, 본문에 세부 조건이 몰림, 합계를 낼 수 있는 표에 합계가 없음, caption에 날짜가 있음 |
| 본문과 그림의 어긋남 | 숫자, 용어, 순서, 화면 상태, 그림 번호가 본문과 표나 그림이나 데모에서 다름 |

`bash .claude/skills/writing-style/check.sh <글 파일>`도 실행합니다. 걸린 줄은 원본과 대조한 뒤 위 목록에 넣습니다. 코드와 인용 같은 실제 예외면 까닭을 밝히고, 검사 결과만으로 문장 전체를 판정하지 않습니다. 정규식이 잡지 못하는 예고 문장과 생략된 설명도 직접 읽어 찾습니다.

## 읽기 전용 범위

- 글, 그림, 데모와 그 밖의 파일을 만들거나 고치지 않습니다. 결과도 마지막 답변으로만 돌려줍니다. write-post가 호출했다면 오케스트레이터가 답변을 `review.md`로 저장합니다.
- 외부 자료와 숫자나 동작을 대조하지 않습니다(fact-check-post의 일). 글 안에서 본문과 표의 값이 다른 것은 보고합니다.
- 제목 길이, 절 개수 같은 형식 검사나 게시 판단은 prepublish-check에 맡깁니다.
- 취향만으로 걸렸다고 적지 않습니다. 독자가 무엇을 알 수 없거나 어느 설명에서 멈추는지 씁니다. 짧은 수정 방향은 제안할 수 있지만 문단을 다시 써 주지 않습니다.

## 결과 형식

```markdown
# 새 독자 검토: {slug}

읽은 파일: src/content/posts/{slug}/index.mdx (총 N줄)
writing-style 검사: 출력 없음 / 걸린 줄 M개
그림 확인: 확인한 그림과 상태 / 확인 못한 그림과 상태

| 파일:줄 | 종류 | 걸린 곳 | 새 독자가 걸린 까닭 | 수정 방향 |
| --- | --- | --- | --- | --- |
| index.mdx:37 | 처음 보는 말 | 「scrollMargin」 | 무엇과 무엇 사이의 거리인지 풀이가 없음 | 처음 쓰는 곳에서 거리의 양 끝을 설명 |

## 먼저 고칠 것

1. 읽다가 막힌 곳 세 개 이내와 그 까닭

## 그대로 두면 좋을 곳

- 설명을 따라가는 데 도움이 된 대목과 줄 번호

## 검토 범위

- 종류별 발견 수, 앞 편 링크로 풀이를 확인한 곳, 확인 못한 것
```

목록은 글의 줄 번호 순서로 씁니다. 그림이나 데모 파일 문제는 그 파일의 경로와 줄 번호, 연결된 글의 줄 번호를 함께 적습니다. 같은 문제가 반복되면 처음 나온 줄에 묶고 다른 줄 번호도 적습니다. 걸린 곳은 원문에서 짧게 따옵니다.

발견하지 못한 종류는 「찾지 못함」으로 적습니다. 확인하지 못한 곳을 문제없다고 판정하지 않습니다.
