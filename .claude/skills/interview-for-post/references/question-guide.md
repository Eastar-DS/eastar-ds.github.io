# 질문을 고르는 기준

## 물을 수 있는 것

이스타만 답할 수 있는 것은 다섯 분류입니다.

| 분류 | 물을 것 | 자료에 이미 있기 쉬운 곳 |
|---|---|---|
| 고른 까닭 | 여러 방법 가운데 왜 그 방법이었는지, 왜 지금 했는지 | ADR의 「무엇을 결정했나」, PR 본문, 개인 노트 |
| 견준 방법 | 실제로 해 보거나 따져 본 다른 방법, 버린 까닭 | ADR의 「트레이드 오프」, 측정 기록의 다른 빌드 |
| 배운 점 | 하기 전과 뒤에 달라진 생각, 예상과 달랐던 것 | 거의 없음. 개인 노트에 있을 수 있음 |
| 다음에 다르게 할 점 | 다시 한다면 바꿀 순서나 방법, 하지 못한 것 | PR의 한계 절, ADR의 「다시 논의해야 할 조건」 |
| 독자에게 바라는 것 | 누가 읽기를 바라는지, 읽고 무엇을 하기를 바라는지 | 없음 |

## 고르는 순서

1. 답에 따라 절이 생기거나 없어지는 질문
2. 답에 따라 글 첫 문단의 결론이 바뀌는 질문
3. 자료끼리 말이 달라서 어느 쪽이 맞는지 정해야 하는 질문
4. `단서만` 자료의 내용을 글에 써도 되는지 확인하는 질문
5. 문단 하나를 더 낫게 하는 질문

5번은 질문이 열 개를 넘으면 가장 먼저 뺍니다.

## 질문의 꼴

- 상황을 짚어서 묻습니다. 「이 작업에서 무엇을 배웠나요」보다 「거리 방식으로 바꾼 날, 행 개수 방식의 무엇이 틀렸다고 보셨나요」가 답하기 쉽고 글에 쓸 수 있는 답이 옵니다.
- 질문 하나에 물음 하나만 넣습니다.
- 답을 이끄는 말을 넣지 않습니다. 「TanStack Virtual과 견주셨죠」가 아니라 「직접 구현 말고 따져 본 방법이 있었나요. 없었으면 없었다고 답해 주세요」로 묻습니다.
- 자료의 사실을 질문에 넣어 이스타가 기억을 떠올리게 돕습니다. 사실에는 자료 번호를 붙입니다.
- 확인 질문은 예, 아니요로 답할 수 있게 쓰되, 글에 쓸 말로 다시 적어도 된다고 덧붙입니다.
- `단서만` 자료를 가리킬 때는 노트의 절 이름과 주제만 말하고 문장을 인용하지 않습니다.

## 묻지 않는 것

- 숫자, 날짜, 파일 이름, 함수 이름처럼 자료에서 확인할 수 있는 사실
- 독자가 궁금해할 것을 대신 물어보는 질문
- 「글에 넣을 만한 이야기가 더 있나요」 같은 넓은 질문. 마지막에 하나만 둘 수 있고 열 개에 포함합니다
- 다른 사람(팀원, 리뷰어)이 한 말과 생각
