# 가상화 다섯 편 사실 대조 API 결과

가상화 시리즈 초안 다섯 편을 Claude Opus 5.5의 독립 API 세션으로 대조했다. 행 범위 편의 스크롤 비율 문장 1곳을 고치고 그 편을 다시 대조했다. 다섯 편 모두 `verify`를 통과했고, `status`는 **최신(2026-11-23), 다름 0건**이다. **출처에 없음 4건과 일부 맞음 43건은 이스타가 검토할 항목**이다.

총 **22회, $21.2494744**를 사용했다. 수치와 개별 판정의 공유용 목록은 [요약 JSON](factcheck-api-2026-11-23.json)에 있다. 대조표 원문, 주장 목록, 받아 둔 웹 원문, 실행 로그는 저장소 밖 작업 폴더에 보관했다.

## 고친 문장

2편의 최초 판정 M19가 「다름」이었다. Knot의 `dbdceceb6` 커밋에서 `getRowOffsets`, `getVisibleRange`, 행 높이 상수를 직접 읽고 함수를 다시 실행했다. `main` 640px, 미리 그릴 거리 325px, 요약 없는 행 100개, 16px 간격에서 스크롤 406번 중 범위 변경은 154번이었다. 이벤트 수를 범위 변경 수로 나누면 약 2.64다.

고치기 전 문장은 다음과 같다.

> 요약 없는 행 100개짜리 카드를 16px씩 내려 보면, 행 하나가 65px이라 범위가 바뀌는 scroll 이벤트는 네 번에 한 번꼴이고 나머지 세 번은 렌더링을 건너뜁니다.

고친 뒤 문장은 다음과 같다.

> 요약 없는 행 100개짜리 카드를 `main` 높이 640px, 미리 그릴 거리 325px로 두고 16px씩 내려 보면, `start`와 `end`가 서로 다른 위치에서 바뀌어 범위가 바뀌는 scroll 이벤트는 두세 번에 한 번꼴이고 나머지는 렌더링을 건너뜁니다.

정본 9장에 따라 `updatedAt: 2026-11-23`과 「고친 내용」을 더했다. 다른 본문 문장은 고치지 않았다. 새 검사자 세션의 재대조는 최신 상태와 다름 0건을 확인했다.

## 이스타가 정할 출처에 없음

아래 문장은 원문에 두었다. 추가 근거를 마련할지, 표현을 고칠지는 이스타가 정한다.

| 편 | 번호 | 줄 | 주장 |
|---|---|---:|---|
| 1편 | M1 | 20 | Knot는 우아한테크코스 팀 프로젝트 |
| 1편 | M9 | 64 | Commit은 메인 스레드가 그린 결과를 합성기 스레드로 넘기는 일 |
| 2편 | M24 | 197 | 참과 거짓 둘뿐이라 Emotion이 만드는 클래스는 둘에서 늘지 않음 |
| 5편 | M4 | 37 | `aria-setsize`와 `aria-posinset`은 화면에 아무것도 그리지 않고 접근성 트리의 값만 바꿈 |

2편의 `disconnect` 설명은 최초 「출처에 없음」에서 재대조 「일부 맞음」으로 바뀌었다. 재대조표는 ResizeObserver 규격의 생존 조건을 근거로 들었고, 「창 크기가 바뀔 때마다」라는 범위는 좁혀 쓸 것을 제안했다. 이 문장은 고치지 않았다.

## 수정된 description의 독립 시험

앞 평가에서 수정한 `prepublish-check` description에 새 질문 16건을 사용했다. 질문은 실행 전에 저장했고, 긍정 8건과 인접 음성 8건 모두 기대한 선택을 했다. 실패 질문은 없다. 비용은 **$1.6164558**다.

앞 평가와 같은 첫 턴 설정으로 Skill, Read, Glob, Grep만 허용했다. 쓰기와 명령 실행은 막았고, 검사자 역할을 덧붙이지 않은 기본 평가 지시문을 사용했다. 각 질문은 새 세션에서 1회 실행했다. 첫 턴의 스킬 선택을 본 시험이며, 후속 작업 수행은 측정하지 않았다. 질문 원문과 실제 선택은 요약 JSON의 `holdout.cases`에 있다.

## 저장된 결과 재채점

API 호출 없이 앞 평가의 결과 15건을 다시 채점했다. 모델 답변은 바꾸지 않았다.

- 확인 표시의 줄 번호를 평가 사본에서 구하고, 같은 표 행에 표시와 위치가 있는지 확인하게 했다.
- 「글 안」이나 「다른 줄」이라는 고정 표현 대신, 다른 실제 줄의 올바른 수치와 근거가 기록됐는지 확인하게 했다.
- 함수 이름 근거는 명령 출력과 원본 코드 인용을 함께 허용하고, 기존 `verify`로 인용을 검사했다.
- 「Lighthouse 휴대폰 점수」라는 검사 이름을 보고 전체의 평가 점수와 구분했다.

## 실행 조건과 검증

22회 모두 모델은 `claude-opus-5-5`, init의 `apiKeySource`는 `ANTHROPIC_API_KEY`였다. 권한 600인 키 파일을 실행기에서 읽어 자식 환경 변수로만 전달하고, 다른 Anthropic 인증과 라우팅 환경 변수는 제거했다. MCP 서버는 모두 비어 있었고, Task, Agent, MCP 도구 호출은 0건이었다. 대조표를 쓰는 검사자 세션은 글을 고치지 않았다.

실행기는 앞 평가의 `scripts/skillApiEval.mjs`를 재사용했다. 기본 예산은 보존하면서 작업별 상한을 받게 했고, 인증이나 정산 오류가 나면 진행 중인 호출도 모두 멈추게 했다. `summarizeSkillApiEval.mjs`는 장부의 상한으로 잔액을 계산한다.

- `pnpm install --frozen-lockfile` 완료
- `pnpm check && pnpm test && pnpm build` 통과, 테스트 501개
- 수정 글의 `writing-style/check.sh` 출력 없음
- `node scripts/checkPost.ts --all --include-drafts`: 실패 0, 경고 5, 통과 215
- 다섯 편 `verify` 통과, `status` 최신이며 다름 0
- 빌드가 만든 글꼴 변경을 원래 상태로 되돌림

경고는 1편과 2편의 h2 수, 1편의 확인 표시, 1편과 2편의 초안 글 링크다. 다섯 편은 모두 `draft: true`다. 작업 브랜치는 `posts/fact-check-api`다. 푸시, main 변경, 외부 게시는 하지 않았다.

원문과 장부는 저장소 밖 `~/.blog-work/_evals/factcheck-api-2026-11-23/`에 있고, 현재 대조표는 각 글의 공용 작업 폴더에 있다. 원문과 로컬 자료 경로는 공유용 JSON에서 제외했다.
