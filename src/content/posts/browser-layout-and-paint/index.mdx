브라우저는 HTML과 CSS를 받으면 스타일 계산, 레이아웃, 페인트, 합성의 네 단계를 거쳐 화면을 그립니다. 어떤 속성을 바꾸느냐에 따라 이 가운데 어디부터 다시 하는지가 달라지고, 그 차이가 곧 체감 속도의 차이가 됩니다.

## 렌더링의 네 단계

화면 한 장이 그려지기까지 브라우저는 아래 순서로 일합니다.

1. **스타일 계산**: 어떤 CSS 규칙이 어느 요소에 적용되는지 정하고, 요소마다 최종 스타일 값을 계산합니다.
2. **레이아웃**: 요소마다 크기와 위치를 계산합니다. 한 요소의 크기가 바뀌면 옆과 아래 요소의 자리도 함께 바뀔 수 있어서 비용이 큽니다.
3. **페인트**: 글자, 색, 테두리, 그림자를 어떤 순서로 칠할지 정하고 픽셀로 칠합니다. 이때 화면은 여러 레이어로 나뉘어 레이어마다 따로 칠해집니다.
4. **합성**: 칠해 둔 레이어들을 올바른 순서와 위치로 겹쳐 한 장의 화면을 만듭니다.

스타일을 바꾸면 브라우저는 바뀐 값이 영향을 주는 단계부터 그 뒤의 단계를 다시 합니다. 그래서 같은 움직임이라도 어떤 속성으로 만드느냐에 따라 다시 하는 일의 양이 크게 다릅니다.

<Figure caption="표 1. 바꾼 속성에 따라 다시 하는 단계" captionSide="top">

| 바꾼 속성의 예 | 다시 하는 단계 |
| --- | --- |
| `width`, `height`, `margin`, `top`, `font-size` | 스타일 → 레이아웃 → 페인트 → 합성 |
| `color`, `background-color`, `box-shadow` | 스타일 → 페인트 → 합성 |
| `transform`, `opacity` | 스타일 → 합성 |

</Figure>

## 레이아웃을 다시 하는 변경

요소의 크기나 위치에 영향을 주는 속성을 바꾸면, 브라우저는 레이아웃부터 다시 계산합니다. 레이아웃이 바뀌면 칠할 내용도 바뀌므로 페인트와 합성까지 모두 다시 합니다.

레이아웃은 보통 프레임마다 한 번, 화면을 그리기 직전에 몰아서 합니다. 그런데 스타일을 바꾼 직후에 `offsetWidth`처럼 레이아웃 결과를 읽으면, 브라우저는 정확한 값을 돌려주려고 그 자리에서 레이아웃을 바로 계산합니다. 이것을 **강제 동기 레이아웃**이라고 합니다. 아래 코드는 반복문 안에서 읽기와 쓰기를 번갈아 해서, 상자 수만큼 레이아웃을 강제로 다시 하게 만드는 흔한 예입니다.

```ts title="resize.ts"
for (const box of boxes) {
  const width = box.offsetWidth; // 읽기: 레이아웃 강제
  box.style.width = `${width * 2}px`; // 쓰기
}
```

<Callout kind="warn">반복문 안에서 레이아웃 결과 읽기와 스타일 쓰기를 섞으면, 반복할 때마다 레이아웃을 강제로 다시 합니다.</Callout>

### 읽기와 쓰기를 나누기

읽기를 먼저 모두 끝내고 쓰기를 나중에 몰아서 하면, 레이아웃은 쓰기가 끝난 뒤 한 번만 계산합니다.

```ts title="resize.ts"
const widths = boxes.map((box) => box.offsetWidth); // 읽기를 먼저 모으고

boxes.forEach((box, index) => {
  box.style.width = `${widths[index] * 2}px`; // 쓰기는 나중에 한꺼번에
});
```

두 예시의 `boxes`는 `[...document.querySelectorAll<HTMLElement>(".box")]`처럼 만든 배열입니다.

## 페인트만 다시 하는 변경

색이나 그림자처럼 모양만 바뀌는 속성은 요소의 크기와 위치를 바꾸지 않습니다. 그래서 브라우저는 레이아웃을 건너뛰고 페인트부터 다시 합니다. 레이아웃보다는 가볍지만, 넓은 영역을 자주 칠하면 여전히 프레임을 놓칠 수 있습니다.

## 합성만 다시 하는 변경

`transform`과 `opacity`는 레이아웃과 페인트를 건너뛰고 합성만 다시 할 수 있는 속성입니다. 요소가 자기 레이어에 올라가 있으면, 브라우저는 이미 칠해 둔 레이어를 옮기거나 투명도만 바꿔 다시 겹칩니다. 합성은 메인 스레드와 따로 도는 합성 스레드에서 처리할 수 있어서, CSS 애니메이션이라면 메인 스레드가 바빠도 부드럽게 움직입니다.

CSS 애니메이션이나 트랜지션으로 `transform`을 움직이면 브라우저가 알아서 요소를 레이어에 올립니다. 미리 올려 두고 싶다면 `will-change: transform`을 쓸 수 있지만, 레이어마다 메모리를 쓰므로 실제로 움직이는 요소에만 붙입니다.

세 경우를 직접 비교해 보겠습니다. 아래 데모에서 속성을 고르고 재생하거나 슬라이더를 움직이면, 미리보기 상자의 그 속성이 실제로 바뀌고 단계마다 다시 한 횟수가 쌓입니다. `width`는 네 단계의 횟수가 모두 늘어나고, `transform`은 레이아웃과 페인트를 건너뜁니다.

## 정리

- 브라우저는 스타일 계산, 레이아웃, 페인트, 합성의 순서로 화면을 그리고, 바꾼 속성이 영향을 주는 단계부터 다시 합니다.
- `width`나 `top`처럼 크기와 위치를 바꾸는 속성은 네 단계를 모두 다시 해서 가장 비쌉니다.
- 레이아웃 결과를 읽기와 스타일 쓰기를 번갈아 하면 레이아웃을 여러 번 강제로 하게 되므로, 읽기와 쓰기를 나눕니다.
- 색만 바꾸면 레이아웃을 건너뛰고, `transform`과 `opacity`는 합성만 다시 합니다.
- 움직임을 만들 때는 먼저 `transform`과 `opacity`로 만들 수 있는지 살핍니다.
