목록 가상화는 행마다 위치를 그리기 전에 계산하고, 화면 구간을 위아래로 넓혀 걸친 행만 그린 뒤, 그리지 않은 행의 높이를 카드 높이와 위쪽 여백으로 채우면 동작합니다.

「주제별」 목록은 문서를 주제별 폴더 카드(`ul`)로 묶고, 스크롤은 창이 아니라 화면 레이아웃의 `main`이 맡습니다. 폴더 틀은 모두 그리고 카드마다 화면 근처의 행(`li`)만 그리므로, 아래 계산은 모두 폴더 카드 하나를 기준으로 합니다.

## 행 높이는 그리기 전에 어떻게 알까

Knot의 문서 행은 제목과 요약을 한 줄에서 말줄임하기 때문에, 요약이 있는지만 알면 행 높이가 정해집니다. 화면 근처의 행을 고르려면 행을 그리기 전에 위치를 알아야 해서 행 높이를 그린 뒤 재지 않고 계산하는데, 글이 길어도 행이 두 줄로 늘어나지 않으니 계산이 맞습니다.

<Figure caption="표 1. 문서 행 높이를 이루는 값 (1rem이 16px일 때)" captionSide="top">

| 부분 | 요약 없는 행 | 요약 있는 행 |
| --- | ---: | ---: |
| 위 여백 | 20px | 20px |
| 제목 한 줄 (1rem, 줄 높이 1.5) | 24px | 24px |
| 제목과 요약 사이 | 없음 | 4px |
| 요약 한 줄 | 없음 | 24px |
| 아래 여백 | 20px | 20px |
| 합계 | 64px (4rem) | 92px (5.75rem) |

</Figure>

두 번째 행부터는 행 사이 구분선 1px이 위쪽 테두리로 그어져 행 높이에 더해집니다. 아래 `getRowOffsets`는 높이 규칙대로 행마다 위쪽 끝의 위치를 쌓아서 행 수보다 하나 긴 배열을 돌려주고, 배열의 마지막 값이 카드 전체 높이가 됩니다.

```ts title="getRowOffsets.ts"
export const getRowOffsets = ({
  documents,
  remPx,
}: GetRowOffsetsParams) => {
  const offsets = [0];

  documents.forEach(({ summary }, index) => {
    const rowHeightRem =
      summary === null
        ? ROW_HEIGHT_REM.withoutSummary
        : ROW_HEIGHT_REM.withSummary;
    const dividerPx = index === 0 ? 0 : ROW_DIVIDER_PX;

    offsets.push(
      offsets[index] + rowHeightRem * remPx + dividerPx,
    );
  });

  return offsets;
};
```

요약이 있음, 없음, 없음인 행 셋이면 첫 행은 구분선 없이 92px이고 둘째와 셋째 행은 64px에 구분선 1px을 더한 65px이라, 돌려주는 값은 `[0, 92, 157, 222]`입니다. 구분선을 빼먹으면 `[0, 92, 156, 220]`, 첫 행에도 넣으면 `[0, 93, 158, 223]`이 되어 행이 하나씩 밀립니다.

`remPx`는 1rem이 몇 px인지를 화면에서 읽은 값이고, 구분선은 px 값이라서 `remPx`를 곱하지 않습니다. 브라우저 설정에서 글자 크기를 키워 1rem이 20px이 되면 행은 80px로 커지지만 구분선은 1px 그대로라서, 요약 없는 행 두 개는 `[0, 80, 161]`이 됩니다. 개선 전 빌드에서 행 1,939개와 카드 28개의 실제 높이를 모두 재어 보니, 1rem이 16px일 때와 20px일 때 모두 계산과 같았습니다.

## 화면 구간은 어떻게 잴까

화면 구간은 카드 맨 위를 0으로 둔 좌표로 잽니다. 페이지 전체를 하나의 좌표로 계산하려면 탭 머리 높이, 폴더 머리 높이, 머리와 카드 사이 12px, 폴더 사이 28px을 모두 JavaScript에 다시 적어야 하고, 디자인이 바뀔 때 CSS와 JavaScript를 함께 고쳐야 합니다. 카드가 실제로 어디에 있는지는 브라우저가 `getBoundingClientRect`로 알려 주므로, 직접 계산하는 값은 카드 안의 행 높이까지로 줄어듭니다.

```ts title="useVisibleRowRange.ts"
const viewStart =
  main.getBoundingClientRect().top -
  card.getBoundingClientRect().top;
const viewEnd = viewStart + main.clientHeight;
```

`viewStart`는 화면 위쪽 끝이 카드 맨 위에서 몇 px 아래에 있는지이고, 카드가 화면 위쪽 끝보다 아래에 보이면 음수가 됩니다. 예를 들어 창에서 `main`의 위쪽 끝이 100px, 카드의 위쪽 끝이 400px에 있고 `main`의 높이가 800px이면, `viewStart`는 100 − 400 = −300이고 `viewEnd`는 500이라서 카드의 처음 500px이 화면에 보인다는 뜻입니다. 빼는 순서를 거꾸로 하면 부호가 뒤집혀, 화면 위로 지나간 카드와 아직 아래에 있는 카드를 서로 바꿔 계산합니다.

## 넓힌 구간에 걸친 행은 어떻게 고를까

`getVisibleRange`는 화면 구간을 위아래로 `overscanPx`(미리 그릴 거리)만큼 넓힌 다음, 넓힌 구간에 조금이라도 걸친 행의 처음과 끝을 `{ start, end }`로 돌려줍니다. 아래 코드는 함수 본문만 줄을 맞춰 실은 것입니다.

```ts title="getVisibleRange.ts" {1-2}
const rangeStart = viewStart - overscanPx;
const rangeEnd = viewEnd + overscanPx;
const rowCount = offsets.length - 1;
let firstInRange = -1;
let lastInRange = -1;

for (let index = 0; index < rowCount; index += 1) {
  const isInRange =
    offsets[index + 1] > rangeStart &&
    offsets[index] < rangeEnd;

  if (isInRange) {
    if (firstInRange === -1) firstInRange = index;
    lastInRange = index;
  }
}

if (firstInRange === -1) return { start: 0, end: 0 };

return { start: firstInRange, end: lastInRange + 1 };
```

i번 행은 아래쪽 끝 `offsets[i + 1]`이 넓힌 구간의 위쪽 끝보다 크고, 위쪽 끝 `offsets[i]`가 넓힌 구간의 아래쪽 끝보다 작을 때 걸친 것으로 봅니다. 두 비교에 등호가 없어서 끝이 딱 맞닿기만 한 행은 빠지고, 예를 들어 행 위치가 `[0, 64, 157, 222, 287]`이고 미리 그릴 거리 없이 화면이 157–600px이면 157px에서 끝나는 1번 행은 그리지 않아 결과가 `{ start: 2, end: 4 }`입니다. `end`는 범위에 들지 않는 첫 행이라서 `documents.slice(start, end)`로 그릴 문서를 고를 수 있고, 걸친 행이 없으면 `{ start: 0, end: 0 }`을 돌려줘서 `slice` 결과가 빈 배열이 됩니다.

요약이 [없음, 있음, 없음, 없음]인 카드가 화면 위쪽 끝보다 조금 위로 올라가 있는 경우로 값이 흐르는 순서를 따라가 보겠습니다.

1. `getRowOffsets`가 `[0, 64, 157, 222, 287]`을 돌려줍니다.
2. 창에서 `main`의 위쪽 끝이 56px, 카드의 위쪽 끝이 −344px, `main`의 높이가 800px이라서 `viewStart`는 56 − (−344) = 400, `viewEnd`는 1,200입니다.
3. 미리 그릴 거리 325px로 넓힌 구간은 75–1,525px입니다.
4. 카드의 아래쪽 끝(287px)은 화면 위쪽 끝(400px)보다 113px 위라서 화면에는 행이 하나도 보이지 않지만, 아래쪽 끝이 75px보다 아래인 1, 2, 3번 행은 넓힌 구간에 걸칩니다.
5. 결과는 `{ start: 1, end: 4 }`이고, 카드는 1, 2, 3번 행을 그립니다.

카드가 화면 밖에 있어도 넓힌 구간에 걸친 행은 미리 그리므로, 위로 스크롤해 카드가 화면에 들어오는 첫 프레임에 빈 칸이 보이지 않습니다. 넓힌 구간에 걸친 행은 언제나 카드 안의 행이라서, 범위를 카드 안으로 자르는 코드도 따로 두지 않았습니다. 미리 그릴 범위를 행 개수가 아니라 거리로 정한 까닭과 325px라는 값은 [3편](/posts/virtual-list-blank-frames/)에서 다룹니다.

## 카드 높이와 첫 렌더링은 어떻게 다룰까

카드 높이는 행을 모두 그린 높이로 고정하고, 그린 첫 행의 위치만큼 위쪽 여백(`paddingTop`)을 줍니다. 첫 렌더링에서는 행을 하나도 만들지 않고, 브라우저가 페인트하기 전에 범위를 구해 다시 렌더링합니다.

```tsx title="DocumentFolder.tsx"
<Card
  ref={cardRef}
  style={{ height: cardHeight, paddingTop: firstRowTop }}
>
```

요약 없는 행 100개짜리 카드를 1,000px 내렸다면 카드 높이는 행을 모두 그린 높이인 6,499px로 두고, 위쪽 여백은 그린 첫 행인 10번 행의 위쪽 끝 649px로 둡니다. 저장소 전역 스타일이 `box-sizing: border-box`라서 위쪽 여백은 카드 높이 안에 들어가고, 카드 높이는 6,499px에서 바뀌지 않은 채 행이 들어가는 안쪽 높이만 6,499 − 649 = 5,850px가 됩니다. 행을 지우거나 그려도 카드 높이가 같아서 아래 폴더가 움직이지 않고, 스크롤바 길이도 행을 모두 그렸을 때와 같습니다.

두 값은 스크롤할 때마다 바뀌어서 인라인 스타일로 넣었습니다. Emotion의 styled 컴포넌트에 값을 넘기면 값마다 새 클래스를 만들어 스타일 시트에 더하므로, 스크롤하는 동안 클래스가 계속 쌓이기 때문입니다.

카드 위치를 `getBoundingClientRect`로 재려면 카드 `ul`이 DOM에 있어야 하는데, 첫 렌더링에서 행을 모두 만들면 행 1,939개를 만든 뒤에 줄이게 되어 가상화로 줄이려던 일을 그대로 하게 됩니다. 그래서 처음 범위를 `{ start: 0, end: 0 }`으로 두고 범위는 `useLayoutEffect`에서 구하며, `main` 높이가 640px이고 요약 없는 행 100개짜리 카드가 맨 위에 있으면 첫 화면은 아래 순서로 나옵니다.

1. 첫 렌더링: 범위가 `{ start: 0, end: 0 }`이라 `li`가 0개이고, 카드 높이는 6,499px입니다.
2. 커밋: React가 카드 `ul`을 DOM에 붙입니다.
3. `useLayoutEffect`: 카드 위치를 재서 `viewStart` 0, `viewEnd` 640으로 범위 `{ start: 0, end: 15 }`를 구해 `setRange`에 넘깁니다.
4. 다시 렌더링: layout effect 안에서 바꾼 상태라서 React가 브라우저의 페인트 전에 다시 렌더링하고 `li` 15개를 붙입니다.
5. 페인트: 사용자가 처음 보는 화면에는 행 15개가 있습니다.

1번부터 4번까지는 브라우저가 페인트하기 전에 한 작업 안에서 이어서 일어나서 사용자에게 보이지 않습니다. `useEffect`를 쓰면 effect가 페인트 뒤에 돌 수 있어서, 1번 결과인 행 없는 카드가 한 프레임 보일 수 있습니다.

## 언제 범위를 다시 구할까

`useVisibleRowRange` 훅은 카드를 감싼 `main`의 scroll 이벤트와 [`ResizeObserver`](https://developer.mozilla.org/en-US/docs/Web/API/ResizeObserver)의 크기 변화 알림을 받을 때마다 범위를 다시 구하고, 다시 렌더링은 범위가 바뀐 때로 줄였습니다. 한 번 스크롤하는 동안 scroll 이벤트가 여러 번 오는데 대부분은 범위를 바꾸지 않으므로, 범위가 같으면 `setRange`에 이전 상태 객체를 돌려줍니다.

```ts title="useVisibleRowRange.ts"
const applyRange = (next: RowRange) => {
  setRange((previous) =>
    previous.start === next.start &&
    previous.end === next.end
      ? previous
      : next,
  );
};
```

요약 없는 행 100개짜리 카드를 `main` 높이 640px, 미리 그릴 거리 325px로 두고 16px씩 내려 보면, `start`와 `end`가 서로 다른 위치에서 바뀌어 범위가 바뀌는 scroll 이벤트는 두세 번에 한 번꼴이고 나머지는 렌더링을 건너뜁니다. 비교 없이 `setRange(next)`를 부르면 `getVisibleRange`가 이벤트마다 새 객체를 돌려주므로, React는 `Object.is`로 다른 상태라고 보고 내용이 같아도 이벤트마다 다시 렌더링합니다.

크기 변화까지 받는 까닭은 scroll 이벤트가 스크롤 위치가 바뀔 때만 오기 때문입니다. 창을 키워 `main`이 높아져도 스크롤 위치가 그대로면 scroll 이벤트가 오지 않아서, 처음 구현에서는 넓어진 화면의 아래쪽이 다음 스크롤 전까지 비어 보일 수 있었습니다.

미리 그릴 거리만큼은 화면 아래에 그려 두었으므로 `main`이 조금 높아질 때는 빈 곳이 생기지 않고, 그려 둔 행의 아래쪽 끝(974px)보다 높아질 때부터 빕니다. `ResizeObserver`로 `main`을 지켜보게 한 뒤에는 크기가 바뀔 때마다 범위를 다시 구합니다.

`observe`를 부르면 브라우저가 첫 알림을 한 번 보내지만, 이미 구한 범위와 같아서 위의 비교가 다시 렌더링을 건너뜁니다. effect의 정리 함수에서 `disconnect`를 빼먹으면 언마운트한 폴더의 콜백이 창 크기가 바뀔 때마다 계속 불리므로, scroll 리스너를 떼는 곳에서 함께 끊습니다.

## 그린 첫 행의 구분선은 왜 어긋났을까

카드의 첫 `li`가 폴더의 첫 행이 아닌데도 구분선을 긋지 않아서 어긋났습니다. 처음 구분선 규칙은 앞에 다른 행이 있는 행에만 위쪽 테두리를 긋는 Emotion의 `& + &` 선택자였고, `getRowOffsets`는 0번이 아닌 행에 모두 1px을 더해 계산하므로, 일부만 그리면 그린 첫 행이 계산보다 1px 짧게 그려지고 아래 행이 모두 1px씩 위에 놓였습니다.

빠진 구분선은 카드의 첫 `li` 것 하나라서 어긋남은 1px보다 커지지 않고, 카드 높이는 380px로 고정되어 있어 마지막 행 아래가 1px 빕니다. 1px이라 눈에 잘 띄지 않지만, 요약 없는 행 100개짜리 카드를 16px씩 내리다 화면 위쪽 끝이 384px에서 400px로 가면 0번 행이 범위에서 빠져 `start`가 1이 되면서 화면 안의 10번 행이 649px에서 648px로 한꺼번에 올라갔습니다. 그래서 구분선을 DOM 순서가 아니라 폴더 안 순서로 긋게 바꿨습니다.

```tsx title="DocumentRow.tsx"
const Item = styled.li<{ $isFirstRow: boolean }>`
  border-top: ${({ theme, $isFirstRow }) =>
    $isFirstRow
      ? "none"
      : `1px solid ${theme.neutral[200]}`};
`;
```

`DocumentFolder`는 `map`이 주는 카드 안 순서에 `start`를 더한 폴더 안 순서로 첫 행인지 정합니다. 카드 안 순서만 보고 `index === 0`으로 쓰면 카드의 첫 `li`마다 참이 되어 고치기 전과 같은 결과가 나오고, 범위가 `{ start: 41, end: 62 }`라면 바르게 고친 코드에서는 `li` 21개 모두 구분선을 긋습니다. 넘기는 값이 참과 거짓 둘뿐이라, styled 컴포넌트에 넘겨도 Emotion이 만드는 클래스는 둘에서 늘지 않습니다.

## 정리

- 행 높이가 요약 유무로만 정해지게 해 두면 행을 그리기 전에 `getRowOffsets`로 위치를 쌓을 수 있고, 구분선처럼 px로 정한 값은 `remPx`를 곱하지 않습니다.
- 화면 구간을 카드 맨 위 기준으로 재면 카드 밖 여백과 머리 높이를 JavaScript에 다시 적지 않아도 되고, 카드가 화면보다 아래에 있으면 `viewStart`가 음수입니다.
- `getVisibleRange`는 넓힌 구간에 걸친 행을 등호 없는 비교로 고르고, `end`를 범위 밖 첫 행으로 둬서 `slice`에 바로 넣습니다.
- 카드 높이를 행을 모두 그린 높이로 고정하고 위쪽 여백으로 그린 첫 행을 내리며, 첫 렌더링은 빈 범위로 시작해 `useLayoutEffect`에서 채웁니다.
- 범위가 같으면 이전 상태를 돌려줘 렌더링을 건너뛰고, scroll 이벤트가 오지 않는 크기 변화는 `ResizeObserver`로 받으며, 구분선은 폴더 안 순서로 긋습니다.
